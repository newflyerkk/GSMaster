# GS Master

本地图片与视频批量压缩，保留文件名称与目录结构，支持预估、备份与安全覆盖。

[下载安装包](https://github.com/newflyerkk/GSMaster/releases)

# GS Master 本地压缩工具

原生 macOS 窗口，离线处理图片与视频。当前构建适用于 **Apple Silicon（M 系列）和 macOS 26 或更新版本**。无需另装 Node、FFmpeg 或 Homebrew，编码器已包含在应用内。

## 使用

1. 打开 `GS Master.app`，也可以将应用复制到「应用程序」。
2. 拖入文件或整个文件夹，也可点击「添加文件 / 文件夹」。自动递归子目录；隐藏子目录、符号链接、应用包和不支持的文件不会进入队列。
3. 勾选要处理的项目，选择「无损优化 / 高清 / 均衡 / 极小」。
4. 选择输出位置；默认不覆盖源文件。点「预估压缩效果」查看每个文件的体积和节省比例，再点「开始压缩」。也可直接压缩。
5. 成功后点击「打开结果」。结果中不生成处理报告。

## 输出和备份

- 不覆盖：在指定位置新建 `GSMaster-日期时间` 文件夹，保留文件名及输入文件夹结构。
- 不同来源同名文件、转格式后的同名冲突，放入独立来源子目录；不擅自修改文件名。
- 原地覆盖：先完成编码、校验和同卷临时文件写入，再原子替换。处理期间源文件变化则停止覆盖。
- 「覆盖前备份」可独立勾选，默认开启。备份在指定位置建立 `GSMaster-备份-日期时间` 文件夹，保持文件名和目录结构。
- 视频转格式只修改扩展名，例如 `旅行.mov` → `旅行.mp4`，始终保留原文件。
- 同格式输出更大时保留源文件内容，标记「无需压缩」。明确请求缩小尺寸、改变帧率或移除音轨时仍执行请求。
- 取消保留已经完成的结果；正在处理的文件不会被半成品替换。取消后退出可能需要等待同步图片编码完成。

## 压缩与预估

| 格式 | 方法 |
| --- | --- |
| PNG | OxiPNG 无损优化、精确调色板；其他档位自动减色并检查黑白背景下的边缘误差 |
| JPEG | MozJPEG 自适应质量、渐进编码、熵优化；严格无损档保留原文件 |
| WebP 静态 | libwebp 无损 / 有损质量优化，保留透明度 |
| HEIC / HEIF | macOS ImageIO 原生质量编码；无损档保留原文件 |
| TIFF 单页 | ImageIO LZW 编码；不通过降色深制造压缩率 |
| GIF 动画 | 调色板压缩，保留帧数、时长和循环次数；无损档保留原文件 |
| MP4 / MOV / MKV / M4V / AVI | H.264 CRF + slow 编码，兼容时复制音轨；可转 MP4 或 WebM |
| WebM | VP9 CRF，兼容时复制 Opus 音轨 |
| 其他支持的视频容器 | MPEG / TS 等可转 MP4/WebM，或尝试无损封装优化 |

无损档视频只重新封装，不重新编码。高清、均衡、极小为有损；四档不保证体积严格递减，已经充分压缩的内容可能没有收益。

图片和不超过 12 秒的视频会完整试压，显示实际编码大小；更长视频抽取前、中、后 3 段，按实际样本时长推算总大小，显示约 65%–140% 的经验区间。该区间不是统计置信区间或体积保证，画面内容变化大时可超出范围。正式输出后显示实际大小。

## 特殊选项与边界

- 最长边上限、视频帧率、移除视频音轨单独列在「特殊选项」。默认保留尺寸、帧率和音轨。
- 图片保持原格式，不自动转换成不支持透明度的格式，因此没有白底替换。PNG/WebP 透明度保留。
- 有损图片重编码会转换为 sRGB 外观并移除部分 EXIF / 附加元数据；无损 PNG 遇到色彩管理数据会保留原文件，避免假无损。
- 高位深图片、动画 WebP/APNG、多页 TIFF/HEIC 暂保留原文件，并在队列标明原因，不展平为静态图片。静态 GIF/BMP 暂不优化。
- 透明视频、HDR 视频和含字幕/数据/封面轨道的视频不自动进行普通有损编码；选择无损优化，或应用会显示具体原因。多画面轨道视频不处理。
- H.264 需要偶数尺寸，奇数宽高会补至下一个偶数。音轨不兼容目标容器时编码为 AAC 或 Opus。
- 单张图片上限 6400 万像素、单文件上限 32 GB。批量顺序执行，避免并行视频编码占满内存。
- 当前是本机构建，采用 ad-hoc 签名，未做 Apple Developer ID 公证；不是 Intel / 老版本 macOS 通用安装包。

## 开发、验证

源码：`Sources/`（原生窗口和 ImageIO）、`engine/`（文件处理与编码）、`tests/engine.test.mjs`。

在仓库根目录：

```sh
./desktop/build.sh
node --test desktop/tests/engine.test.mjs
```

构建脚本自动复制本机 Node/FFmpeg/ffprobe 和依赖库，改为应用内相对路径并签名，不修改本机安装。HEIC 测试需要系统图像编码服务，在限制硬件访问的沙箱中可能失败。

测试覆盖：递归去重、透明 PNG 四档、原名/目录/冲突处理、开启或关闭备份、损坏文件隔离、取消保护、视频抽样/转格式/音轨/时长、GIF 帧数/循环/时长、JPEG/WebP/HEIC/TIFF、尺寸/帧率/静音。另已通过原生界面的文件夹导入、预估和批量输出验收。

## 记住上次设置

## 更新日志

### v1.4.0 保存位置与名称

先压缩到本机待保存区，完成后弹出保存位置选择，并记住上次位置。取消选择时保留结果，可点击“保存结果…”继续；重开应用仍可继续保存。保存成功后清理待保存区。

ZIP 文件名兼容未标记 UTF-8 的中文名称及 GBK 名称。原地覆盖文件/文件夹沿用原路径与名称，ZIP 以原包名重新打包、校验并原子替换，未参与处理的条目保留。RAR/7z 暂不支持原格式重打包，请取消原地覆盖后另存。备份目录为 `backup_原名称`（存在同名时加序号），内部保留原文件名和相对目录。生成物不含 JSON 处理报告。

### v1.3.0 设置记忆与压缩包导入

自动保存勾选项和输出设置，下次打开恢复。支持导入 ZIP / RAR4 / RAR5 / 7z：仅读取支持的素材，跳过隐藏文件与链接；不支持加密、分卷及嵌套压缩包。DC Master 解压后图片单批上限 128 MB，GS Master 单包素材上限 1 GB。GS Master 压缩包素材始终输出到结果文件夹，不改写原压缩包。

### v1.2.2 蓝色玻璃风格

- 对齐 Figma 插件最新蓝色主题：蓝色渐变胶囊按钮、浅蓝灰背景、半透明卡片及细描边。
- 应用图标同步改为蓝色；保留 44pt 主要操作按钮和紧凑布局。
- 适配深色外观及减少透明度设置。

### v1.2.2 品牌名称统一

产品显示名称统一为 **GS Master**，安装包与界面同步更新。

### v1.1.1 操作区优化

- 添加、选择文件和底部操作按钮放大，主要操作使用靛蓝高亮。

### v1.1.0 界面与工作流

- 880×660 默认窗口，最低 800×580；原生 Liquid Glass 控件、紧凑设置区和浅色/深色适配。系统降低透明度时使用实色面板。
- 新导入的一批文件置于列表顶部，批内顺序不变，已有文件去重。
- 完整试压后，点击缩略图或压缩后大小打开原文件与结果对照。长视频打开明确标注的压缩抽样片段。原地覆盖完成后仅显示压缩后文件，不将覆盖后的文件冒充原图。
- 仅压缩成功后自动取消勾选；预估和失败不会取消勾选。
- 历史记录保存最近 500 条完成结果，重启保留；点击条目在 Finder 中选中输出文件。文件已移走/删除时提示无法定位。清空历史不删除文件。
- 历史文件位于 `~/Library/Application Support/GS Master/history.json`；包含本机输出路径，不上传。

界面参考 Apple Liquid Glass，并使用 SwiftUI 原生 glassEffect API：
https://developer.apple.com/documentation/swiftui/view/glasseffect(_:in:)

## v1.5.0 视频转 GIF

视频输出新增 GIF，支持预估和动图预览，转换后手动选择保存位置。使用自适应调色板与抖动，默认无限循环、不保留音轨。高清/均衡/极小默认最长边为 960/640/480、帧率为 15/12/8，可在特殊选项覆盖。GIF 最多 256 色，有损且体积可能大于原视频；无损档仍只保留原格式。

## v1.6.0 视频设置与播放预览

- 视频设置单独分组，格式选项改为“视频格式转为”；选择转换格式后自动展开特殊选项。图片尺寸与视频尺寸分别保存。
- 新增“不压缩”，同格式图片和视频保留原文件字节。无损和不压缩均可进行兼容容器转换，不兼容的编码会提示改用有损档位。
- GIF 在所有档位均可转换，最多 256 色，不能保证无损；不压缩/保色优先默认保留尺寸及源帧率（最高 50 fps，受 GIF 时间精度限制）。
- 对照预览内直接播放视频和 GIF；视频默认静音并提供播放控制，GIF 可暂停。系统不支持的编码仍可用外部播放器打开。
- 主操作按钮改为“开始”。

验证：23 项引擎测试通过，包含字节不变、无损转封装及两档 GIF 转换；原生应用构建通过。
